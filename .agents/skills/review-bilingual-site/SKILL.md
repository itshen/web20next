# 双语网站文案审校

让中文与英文表达相同的事实、动作、条件和确定程度，同时让各自的语言自然。遵循目标项目自己的品牌与语言约定，不把某个项目的口号、域名、配色或 URL 方案推广到其他项目。

## 确定来源与影响范围

- 读取目标仓库适用的 AGENTS.md，以及现有品牌、国际化和分享资源约定；不假定中文必然是唯一原稿。用户已确认的口号与专有名称优先。
- 找到真正的源文件：语言字典、文章、贡献指南、模板及图片生成器。搜索同一文案在标题、说明、按钮、空状态、替代文本、元信息、Feed 和分享图片中的使用位置。
- 区分站方文案与用户提供的内容。没有额外授权，不翻译站主名称、个人介绍、作品标题或其他投稿原文。
- 英文专用的机器文档可以保持英文；核对其规则与其他语言的用户说明是否一致，不为了形式对称新增语言版本。

## 审校语义与表达

逐项或逐段比较以下内容，先消除意义偏差，再改善语言：

- 主体与动作：是拥有网站、分享网站，还是创建网站？是准备资料、提交请求，还是已经发布？
- 范围与条件：字段、数字、权限、可选项、审核要求、状态及不确定性是否相同？某一语言是否擅自增加保证或省略条件？
- 语气与术语：是否符合项目的参与关系？同一个按钮、对象和功能是否使用一致名称？
- 自然程度：英文按常用搭配和语序表达；保留原意，不为字面对齐制造生硬句子。必要时一起修正两种语言中含混的表述。
- 结构与数据：保留占位符、代码字段、命令参数、出处及代码示例含义。遵循项目对功能地址和阅读导航的不同路由规则。

只保留最终文案；除非用户要求审校报告，不在产品界面或规范中加入翻译过程、修改历史或“此处为了……”等解释。

## 同步与验证

- 修改源文件，通过项目现有生成方式更新衍生产物，不手改生成 HTML 或在图片上覆盖文字。
- 文案进入分享图片时，重新生成受影响的语言和图片类型；查看实际图片，检查字体、换行、遮挡和域名/行动入口的可读性。纯文案与向量排版优先沿用现有代码生成器。
- 使用项目已有的类型、语言键、占位符和内容结构检查。不要把测试通过说成语义或地道程度已获证明，也不为低影响修改添加逐字镜像测试。
- 预览受影响页面的两种语言。长英文可能改变按钮宽度、导航换行和消息区域高度；检查桌面和手机。涉及复制操作时核对完整文本与失败后的手动复制方式。
- 运行与变更相关的构建和回归检查，更新静态预览。测试通过且没有新问题时停止扩展验证。

## 交付

简要说明修正了哪些实质性偏差、覆盖了哪些页面或资源、实际完成哪些验证。对尚未验证的项目如实说明。审校不额外授权提交、推送、部署或向外部服务发布内容；按用户当前授权与仓库约定执行。
